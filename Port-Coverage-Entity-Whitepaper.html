Coverage Score & Entity Expansion for AI Retrievability_

A two-vertical, multi-model benchmark validating prompt-driven coverage scoring and entity gap analysis as signals for improving AI citation completeness. Conducted as pre-build validation for a planned AI Spider module.

Abstract

This paper documents pre-build validation research for a Coverage Score and Entity Expansion module planned as a future feature addition to AI Spider, a proprietary locally-hosted website crawler and AI retrievability audit platform. Unlike the Competitive Content Intelligence module validated in Working Paper No. 001 — which compares pages against each other — this module introduces a three-stage reasoning workflow: the LLM first generates an independent expected topic set for a given user query, then evaluates the target page against those expectations, then identifies entity gaps relative to competitor pages.

This is a harder task. It requires the model to reason about completeness from first principles, not just perform pairwise comparison. Research involved designing a structured three-stage prompt, building a two-vertical test set (AI/GEO tools and roofing/home services), establishing ground truth manually for both verticals, and running the identical prompt across four language models.

Research Conclusion

Prompt-driven coverage scoring is a valid signal for AI retrievability improvement when powered by a frontier model. Claude Sonnet 4.6 and ChatGPT GPT-5.5 produce calibrated, accurate coverage scores. Gemini 3.5 Flash introduces a specific failure mode unique to this module: under-generating the expected topic set in Stage 1, which mechanically inflates the coverage score. Qwen2.5 3B fails completely for the second consecutive benchmark. The module will be built using cloud LLM APIs with user-supplied keys, defaulting to Claude or GPT-class models.

1. Background and Research Motivation

Working Paper No. 001 established that structured content gap analysis is a valid signal for AI retrievability improvement. That research validated the Competitive Content Intelligence module. This paper addresses a distinct but related question. CCI tells you what competitors have that you don't. The Coverage Score and Entity Expansion module answers something different: does your page contain what a complete, authoritative answer to the user's query should contain — regardless of what competitors happen to cover?

"A page can match or exceed its competitors in content depth and still be incomplete in absolute terms - missing topics that any expert would expect a comprehensive answer to include, and entities that AI models have learned to associate with the query."

This distinction matters because AI models do not only cite pages that outperform competitors. They cite pages that are sufficiently complete relative to the query's information need. A page in a low-quality competitive set could outperform all competitors and still be invisible in AI-generated answers because it fails an absolute completeness threshold.

Before building this module, three questions needed validation:

  • Q1 - Can LLMs generate accurate expected topic sets? Stage 1 asks the model to generate what a complete answer should contain independently. Is this reliable and calibrated?
  • Q2 - Does topic count in Stage 1 affect coverage accuracy downstream? If models generate different numbers of expected topics, do their coverage scores diverge — and in which direction?
  • Q3 - Does the methodology generalise across domains? WP001 tested only AI/GEO tools. This research adds a roofing vertical to validate domain-agnostic reliability.

2. Research Methodology

2.1 The Three-Stage Reasoning Framework

The module requires the LLM to reason in three sequential stages — each dependent on the quality of the previous.

STAGE 01

Expected topic generation

Given the user query, the model independently generates what a complete authoritative answer should contain. Establishes the completeness ceiling.

Query: "Best AI visibility tools" → Expected: Pricing, citation tracking, entity tracking, GEO, integrations...

STAGE 02

Coverage evaluation

The target page is evaluated against the Stage 1 expected topic set. Coverage Score = covered topics / total expected topics.

Covers: Pricing, Sentiment, SoV. Missing: Citations, Entities, GEO, MCP → 12/20 = 60%

STAGE 03

Entity gap analysis

Named entities on competitor pages but absent from the target are identified. Entity Coverage Score calculated.

Competitors mention: Perplexity, MCP, Mistral, Llama, Gartner. Target missing: all five.

Figure 1. The three-stage reasoning framework. Stage 1 quality is the ceiling for all downstream outputs.

2.2 Prompt Design

A single standardised prompt was designed for both verticals. The key structural distinction from WP001: Stage 1 explicitly permits use of the model's query understanding, while Stages 2 and 3 are restricted to provided content only. This split was the most consequential prompt design decision — without it, models blend training knowledge into coverage evaluation, making Stages 2 and 3 unverifiable.

Prompt Template — v1.0 All 4 models identical · Both verticals
Content omitted

// SYSTEM ROLE

You are a Coverage Score and Entity Expansion engine. You will complete THREE stages of reasoning.

Do not use external knowledge in Stages 2 and 3. Stage 1 should reflect your understanding of what a complete answer to the prompt requires.

// OUTPUT FORMAT — strictly enforced

STAGE 1 — EXPECTED TOPIC SET
- Expected topics: [numbered list generated from query understanding]
- Total expected topics: [number]

STAGE 2 — COVERAGE SCORE
- Topics covered: [checkmarks] / Topics missing: [crosses]
- Coverage Score: [covered / total as percentage]

STAGE 3 — ENTITY GAP ANALYSIS
- Entities on target / Absent from target but on competitors
- Entity Coverage Score + Recommended entity additions

RECOMMENDATIONS
- Priority 1 / 2 / 3 with specific content additions
Respond only with the structured report. No commentary outside the format.

Figure 2. Full prompt template. Colour coding: green = role constraint, purple = output format, red = strict enforcement.

2.3 Two-Vertical Test Set

Two verticals were selected to test domain generalisability — a concern not addressed in WP001.

  • V1 — AI/GEO Tools: "Best AI visibility tools" — Target: Semrush AI Visibility Toolkit. Competitors: Peec AI, Rankshift, Promptwatch, OtterlyAI. Ground truth: 17 expected topics. Target baseline: ~35% coverage.
  • V2 — Roofing: "How to choose a roofing contractor" — Target: This Old House roofing guide. Competitors: Angi (two pages), Bob Vila. Ground truth: 17 expected topics. Target baseline: ~24% coverage.

4. Key Findings

F1

Prompt-driven coverage scoring is valid

All three frontier models produced Stage 1 topic sets meaningfully aligned with the manually derived ground truth in both verticals. The methodology works because the task is well-defined, not because any one model is exceptional at it.

F2

Stage 1 topic count is the critical variable

Coverage score accuracy is determined almost entirely by how many expected topics the model generates in Stage 1. Gemini generated 9 and produced 78%. Claude generated 20 and produced 60%. The target page did not change. Stage 1 quality is the ceiling for everything downstream.

F3

Gemini's failure mode is module-specific

In WP001 (pairwise comparison), Gemini was rated "Usable." In this benchmark it is "Not recommended." Topic bundling — harmless in comparison tasks — directly inflates coverage scores in this module. This is not a general Gemini weakness; it is a specific incompatibility with Stage 1 requirements.

F4

Methodology generalises across domains

Claude and ChatGPT produced consistent output quality across both the AI/GEO technical vertical and the roofing practical vertical. Topic counts, entity detection, and recommendation specificity were comparable. The module can be applied to any vertical without domain-specific prompt tuning.

F5 — New finding unique to this module

Qwen2.5 3B fails for the second consecutive benchmark — confirming the 7B+ threshold

The same failure mode appeared across both verticals and both benchmarks. Qwen listed Stage 2 topics as simultaneously covered and missing, then computed 0% despite the contradiction. This is the second consecutive failure with a different task type and different domains — confirming the failure is not task-specific or prompt-fixable. WP001's finding stands: the minimum viable local model threshold for this class of workflow is 7B parameters or above.

"Coverage score accuracy is a function of Stage 1 quality, not Stage 2 quality. A poorly calibrated Stage 1 produces a plausible-looking coverage score that systematically misleads users into thinking their page is more complete than it is. The module must either use a model reliably generating 18-25 expected topics, or enforce a minimum expected topic count in post-processing."

5. Implications for AI Spider

  • 01

    Claude or GPT-class as default model — Gemini downgraded

    Gemini 3.5 Flash is downgraded from "Usable" to "Not recommended" for this specific module due to Stage 1 under-generation behaviour. The module will default to Claude or ChatGPT-class models. Gemini remains acceptable for the CCI module where Stage 1 is not required.

  • 02

    Minimum expected topic guard will be enforced

    A post-processing check will enforce a minimum expected topic count before calculating the coverage score. If Stage 1 produces fewer than 15 topics, the system will either retry or flag the result as potentially unreliable. This prevents inflated scores from thin topic sets from reaching the user.

  • 03

    All three stages surfaced separately in the UI

    Because Stage 1 quality is visible and auditable, the AI Spider dashboard will surface all three stages as separate panels. Users can inspect the expected topic set before trusting the coverage score — adding a layer of transparency that pure numeric outputs lack.

  • 04

    Module is domain-agnostic by design

    The roofing vertical result confirms no domain-specific prompt tuning is required. The module works for any vertical where a user can provide a target URL, 1-4 competitor URLs, and a query. Immediately applicable to local businesses, service providers, and content-heavy marketing pages.

  • 05

    Entity expansion integrates with RankScan for priority ranking

    The Stage 3 entity gap output identifies which entities competitors mention that the target page omits. Combined with RankScan — which tracks brand and entity mention frequency in AI-generated answers — entity additions can be prioritised by their observed citation frequency. This creates a closed loop: identify the gap, add the content, verify the citation rate improves.

6. Next Steps

  • 6.1 Module build — AI Spider Coverage Score tab: Standalone tab independent from core crawl. Inputs: user query, target URL, up to 4 competitor URLs. Outputs Stage 1 expected topics, Stage 2 coverage score with covered/missing breakdown, Stage 3 entity gap list, prioritised recommendations. Minimum topic guard enforced before score calculation.
  • 6.2 Stage 1 minimum topic calibration: Systematic testing across 10 additional verticals to establish the reliable guard threshold. Current evidence suggests 15 topics is a practical minimum; high-complexity verticals (legal, medical, financial) may require 20+.
  • 6.3 RankScan integration for entity priority ranking: Matching Stage 3 entity gap output against RankScan citation data to rank missing entities by their observed frequency in AI-generated answers — bridging content audit and AI visibility measurement.
  • 6.4 Longitudinal validation: Following coverage-informed content updates on target pages, citation rates tracked via RankScan over 90 days. Findings will form the basis of Working Paper No. 003.
  • 6.5 7B+ local model re-evaluation: Once Llama 3.1 8B or Qwen2.5 7B are tested on the same three-stage prompt, a minimum viable local model recommendation will be published. WP001 established the 7B threshold for pairwise comparison; this benchmark will test whether a higher threshold applies to this more demanding task.

4. Key Findings

F1

The premise is validated

All three frontier models produced coherent, accurate, actionable content gap reports from the same prompt. The methodology reliably surfaces entity, topic, and phrase gaps that a subject-matter expert independently confirmed as real and relevant to AI citation likelihood.

F2

3B models fail at multi-source reasoning

Qwen2.5 3B exhibited critical role confusion - attributing competitor content to the target page - invalidating its entire output. This is not a prompt engineering failure. It is a fundamental reasoning capacity limitation at 3B scale when tracking 5 distinct content sources simultaneously.

F3

Claude: depth. ChatGPT: breadth.

Claude produced fewer but more precise gaps (14 topics vs ChatGPT's 37), with significantly higher recommendation specificity - identifying conversion friction, buyer personas, and vocabulary alignment that ChatGPT missed or listed generically.

F4

Minimum viable threshold is 7B+

A locally-hosted model powering the CCI module would need at least 7B parameters to handle multi-source role tracking reliably. The module will use cloud APIs with user-supplied keys rather than bundled local inference.

"The most practically significant finding is not which model scored highest - it is that the 3B local model failed in the specific way most dangerous for a production feature: silently producing plausible-looking but inverted output, with no error signal."

5. Implications for AI Spider

  • 01

    CCI module will use cloud API with user-supplied key

    Local model inference is not viable at any parameter size currently practical for desktop deployment. The module will integrate via OpenAI, Anthropic, or Google API endpoints - keeping AI Spider dependency-free while enabling the feature for users who want it.

  • 02

    Analysis scoped to URL level, not site level

    URL-level comparison produces better signal quality, lower token cost, and more actionable recommendations. Models performed best when given focused, well-scoped content rather than broad site summaries.

  • 03

    Entity gap is the highest-value dimension for AI retrievability

    Entities are primary citation triggers in AI search. A page that lacks the entities an AI model associates with a topic will not be cited regardless of its authority or technical health - making entity gap the most actionable output of the CCI analysis.

  • 04

    Vocabulary alignment is underserved by current SEO tooling

    The phrase gap dimension revealed pages that were technically comprehensive but used outdated terminology. The target page used "AI search" exclusively, missing the dominant category term "GEO" used by all four competitors. AI models trained on current content are sensitive to this vocabulary mismatch.

  • 05

    One structured prompt replaces hours of manual audit work

    The benchmark confirms that a single well-structured prompt reliably surfaces gaps that would take a human analyst several hours to compile manually. This makes the CCI module a high-leverage addition to AI Spider's existing deterministic audit capabilities.

6. Next Steps

  • 6.1 Module build - AI Spider CCI tab: Standalone tab within AI Spider, independent from the core crawl. Accepts target URL plus up to 4 competitor URLs. Outputs all six analytical dimensions in a structured results dashboard.
  • 6.2 Multi-vertical prompt testing: Additional testing planned across law, healthcare, insurance, and construction verticals to validate prompt robustness across different content types and entity vocabularies.
  • 6.3 Longitudinal citation tracking: Following CCI-informed content updates, AI citation rates will be tracked across ChatGPT, Claude, Gemini, and Perplexity using RankScan to measure whether closing identified gaps correlates with measurable citation improvement.
  • 6.4 7B+ local model re-evaluation: Once Llama 3.1 8B or Qwen2.5 7B are tested on the same prompt, a minimum viable local model recommendation will be published as an addendum to this paper.
