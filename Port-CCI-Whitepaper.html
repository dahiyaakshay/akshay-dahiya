AI Spider – Locally-Hosted AI Retrievability & Technical SEO Crawler Platform_

A deterministic, session-based website crawler built for AI retrievability auditing, technical SEO analysis, and content intelligence — modeled after Screaming Frog but purpose-built for the AI-native search era. No LLM dependency. No data sent externally. Runs entirely on your machine.

Node.js Express SQLite React 19 TypeScript 5.9 Vite 7 Tailwind CSS v4 Cheerio TF-IDF PageRank HITS Algorithm

Project Overview

Technical SEO tools were not built for the AI-native search era.

Modern website auditing requires:

  • AI retrievability scoring per page
  • Deterministic signal extraction without LLM dependency
  • Content chunking and section strength analysis
  • Robots.txt AI bot access auditing
  • Citation readiness detection
  • PageRank and HITS authority propagation
  • Full link graph analysis
  • Session-based local data storage
  • Unlimited crawl depth and URL count

Existing crawlers provide:

  • HTTP status code checking
  • Basic metadata extraction
  • Redirect chain detection
  • Broken link identification
  • Page speed metrics

They do not provide:

  • AI retrievability scoring
  • Bot access auditing for GPTBot, ClaudeBot, Perplexitybot
  • Content extractability and structure scoring
  • Chunk-level section strength analysis
  • Citation signal detection
  • HITS hub and authority propagation
  • N-gram phrase extraction across all pages
  • llms.txt and ai.txt discovery
  • Locally-hosted, zero-cloud architecture

They were not designed for AI-native search visibility.

AI Spider was built to solve that gap.

It is not a basic crawler. It is a full-stack AI retrievability and technical SEO auditing platform.

What It Does

AI Spider enables SEO professionals and developers to:

  • Crawl entire websites with unlimited URL depth and count
  • Score every page for AI retrievability across 5 dimensions
  • Audit which AI bots can and cannot access each page
  • Analyse content structure, chunking quality, and section strength
  • Detect citation signals — statistics, dates, sources, tables, lists
  • Compute PageRank and HITS authority across the internal link graph
  • Identify duplicate, near-duplicate, and orphan pages
  • Extract N-gram phrases from all crawled content
  • Analyse redirect chains, canonical conflicts, and hreflang errors
  • Store all session data locally in SQLite — no external data transfer

It is a unified AI-native crawl intelligence system running entirely on your machine.

Core Capabilities

  • AI Retrievability Scoring Engine

    Every crawled page receives a composite AI Retrievability Score (0–100) computed from five deterministic sub-scores: Extractability, Structure, Citability, AI Crawlability, and Chunk Quality. Scores are computed post-crawl without any LLM API calls — entirely from HTML signal extraction, content chunking, and rule-based scoring logic.

  • AI Bot Access Auditing

    Parses robots.txt to determine access permissions for GPTBot, ClaudeBot, Perplexitybot, Applebot, CCBot, Google-Extended, and Diffbot per page. Detects data-nosnippet attributes, max-snippet directives, and noindex signals that block AI content extraction. Surfaces which pages are invisible to AI crawlers and why.

  • Content Chunking & Section Strength

    Converts page HTML to Markdown, splits content into H2-delimited chunks, and scores each chunk for word count, sentence density, list presence, table presence, numerical data, and outbound links. Section Strength Score reflects how well each content section is structured for AI extraction and citation. Orphan chunks (no heading) score lower.

  • Link Graph Intelligence — PageRank & HITS

    Extracts the complete internal link graph from crawled pages and computes normalised PageRank scores (0–100) across all pages. Also runs the HITS algorithm to compute Hub Scores (pages that link to authoritative destinations) and Authority Scores (pages endorsed by strong hubs). Identifies buried authority pages, orphan pages, and dead-end link structures.

  • Citation Readiness Detection

    Scores each page for citation signals that AI systems use when selecting content to cite: statistical data, date references, source attributions, blockquote presence, HTML tables, and ordered/unordered lists. Citation Score (0–100) reflects how citable a page is in AI-generated responses — a signal beyond traditional SEO metrics.

  • 17-Tab URL Intelligence Interface

    Every crawled URL is surfaced across 17 specialised analysis tabs: URL Table, Content, Technical, Images, Links, Redirects, Canonicals, Structured Data, Issues, AI Signals, Authority, Citation, Section Strength, N-Grams, Architecture, Page Rank, and Visualisations. Column-resizable tables, real-time filtering, and PageIntelligencePanel slide-in drawer for per-URL deep dives.

  • N-Gram Phrase Intelligence

    Extracts 1–4 gram phrases from title, meta description, headings, body, anchor text, and image alt attributes across all crawled pages. Ranks phrases by frequency and page coverage. Reveals the actual topic vocabulary of a site as AI systems see it — not keyword rankings, but content-level phrase density and distribution.

  • Duplicate & Near-Duplicate Detection

    Uses SHA-256 content hashing for exact duplicate detection and TF-IDF cosine similarity for near-duplicate identification. Flags pages with content similarity above threshold, surfaces the closest matching URL, and identifies canonicalisation opportunities. Prevents AI systems from encountering diluted or conflicting page signals.

  • Session-Based Local Architecture

    Every crawl creates a fresh SQLite session database stored locally. No data is sent to external servers, no API keys required for core functionality, and no usage limits. Sessions can be saved as .aispider files and reloaded for future analysis. Supports concurrent crawl configuration: concurrency, crawl delay, depth, user agent, custom headers, cookies, JS rendering via Playwright, and robots.txt respect.

Pre-Build Validation Research · Working Paper No. 001 · 2025-2026

Competitive Content Intelligence for AI Retrievability

Before building the Competitive Content Intelligence module into AI Spider, I conducted original research to answer two questions: Is structured content gap analysis a valid signal for improving AI citation likelihood? And which class of language model can reliably power this analysis at scale? This section documents that research in full.

Research Conclusion

Structured content gap analysis is a valid and actionable signal for AI retrievability improvement. Large frontier models (Claude Sonnet 4.6, ChatGPT o3, Gemini 3.5 Flash) perform reliably on this task. Models below the 7B parameter threshold fail at multi-source role tracking and produce unreliable gap attribution. The CCI module will be built using cloud LLM APIs with user-supplied keys.

1. Background and Research Motivation

The shift from keyword-based search to AI-generated answers has created a new visibility problem for brands and local businesses. In traditional SEO, ranking was largely a function of authority signals, backlinks, and keyword coverage. In generative search, a page must also satisfy a different criterion: it must contain the information an AI model expects to see in order to cite it as a source.

This creates a gap that existing SEO tools do not adequately address. Most crawlers and audit platforms measure technical health, keyword coverage, and backlink profiles. None of them measure content completeness relative to what AI models actually cite.

"A page can rank on page one for a target keyword and still be completely invisible in AI-generated answers - not because of technical issues, but because it is missing the specific entities, topics, and terminology that competing pages contain."

AI Spider performs technical AI retrievability auditing - checking for crawlability, structured data, content signals, and citation readiness. The Competitive Content Intelligence module is a planned addition that would extend AI Spider into the content layer: identifying precisely what information a page is missing relative to its competitive set.

Before building this module, two questions needed validation:

  • Q1 - Is the premise valid? Does structured content gap analysis between a target page and competitors actually surface meaningful differences that affect AI citation likelihood?
  • Q2 - Which model is right for this task? Do all LLMs perform adequately, or is there a meaningful capability threshold? Can a smaller local model be used to preserve offline functionality?
2. Research Methodology

2.1 The 6-Dimension Analysis Framework

The CCI framework analyses one target URL against a set of competitor URLs across six structured dimensions. Each dimension surfaces a specific type of content gap known to affect AI retrievability.

DIM 01

Information Gain

Unique value the target provides that competitors lack

DIM 02

Entity Gap

Named entities competitors mention that the target omits

DIM 03

Topic Gap

Subject areas covered by competitors but absent from the target

DIM 04

Phrase Gap

Industry terminology competitors use that the target lacks

DIM 05

Coverage Score

Percentage of competitor topics addressed by the target

DIM 06

Recommendations

Prioritised content additions ranked by likely impact

2.2 Test Set

Five pages from the AI visibility and GEO tools vertical were selected - all covering overlapping topics but from distinct companies:

  • Target: Semrush AI Visibility Toolkit - product knowledge base page, marketing-focused, data-rich but narrow in GEO vocabulary
  • C1 - Peec AI: AI search analytics. Strong on metrics framing. MCP integration.
  • C2 - Rankshift: Covers ChatGPT, Perplexity, Claude, Gemini, Mistral, Llama. AI crawler log monitoring. UI-based response capture.
  • C3 - Promptwatch: Entity Tracker, agentic shopping data, publish-to-citation timeline, content creation features.
  • C4 - OtterlyAI: 30,000+ users, Gartner recognition, Microsoft Copilot tracking, free GEO tools and marketplace.

This vertical was chosen because the researcher has deep domain knowledge, enabling accurate manual ground-truth assessment of model outputs.

2.3 Models Tested

Claude Sonnet 4.6

Anthropic / Cloud API

RECOMMENDED

Large frontier model. Best recommendation specificity. Identified UI vs API distinction, publish-to-citation timeline, digital PR persona gap, and free trial conversion friction.

ChatGPT o3

OpenAI / Cloud API

VIABLE

Large frontier model. Highest entity breadth (23 identified) but some inflation. Caught agentic shopping gap and all major entities. Good format compliance.

Gemini 3.5 Flash

Google / Cloud API

USABLE

Large frontier model. Good on GEO terminology gap and free trial gap. Minor scoring inconsistency. Slightly lower topic count than actual ground truth.

Qwen2.5 3B Instruct

Alibaba / Local via LM Studio

NOT VIABLE

3B local model. Critical role confusion - attributed competitor content to target page. Entity overlap reported as 0% (incorrect). Information Gain Score of 100/100 (hallucinated). Recommendations generic.

4. Key Findings

F1

The premise is validated

All three frontier models produced coherent, accurate, actionable content gap reports from the same prompt. The methodology reliably surfaces entity, topic, and phrase gaps that a subject-matter expert independently confirmed as real and relevant to AI citation likelihood.

F2

3B models fail at multi-source reasoning

Qwen2.5 3B exhibited critical role confusion - attributing competitor content to the target page - invalidating its entire output. This is not a prompt engineering failure. It is a fundamental reasoning capacity limitation at 3B scale when tracking 5 distinct content sources simultaneously.

F3

Claude scores best on depth; ChatGPT on breadth

Claude produced fewer but more precise gaps (14 topics vs ChatGPT's 37), with significantly higher recommendation specificity - identifying conversion friction, buyer personas, and vocabulary alignment that ChatGPT missed or listed generically.

F4

Minimum viable threshold is 7B+ parameters

A locally-hosted model powering the CCI module would need at least 7B parameters to handle multi-source role tracking reliably. The module will use cloud APIs with user-supplied keys rather than bundled local inference.

"The most practically significant finding is not which model scored highest - it is that the 3B local model failed in the specific way most dangerous for a production feature: silently producing plausible-looking but inverted output, with no error signal."

5. Implications for AI Spider
  • 01

    CCI module will use cloud API with user-supplied key

    Local model inference is not viable at any parameter size currently practical for desktop deployment. The module will integrate via OpenAI, Anthropic, or Google API endpoints, keeping the core AI Spider platform dependency-free while enabling the feature for users who want it.

  • 02

    Analysis scoped to URL level, not site level

    URL-level comparison produces better signal quality, lower token cost, and more actionable recommendations. This aligns with benchmark findings - models performed best when given focused, well-scoped content rather than broad site summaries.

  • 03

    Entity gap is the highest-value dimension for AI retrievability

    Across the benchmark, entity gaps were the most consistently identified and most actionable output. In the AI search context, entities are primary citation triggers. A page that lacks the entities an AI model associates with a topic will not be cited regardless of its authority or technical health.

  • 04

    Vocabulary alignment is underserved by current SEO tooling

    The phrase gap dimension revealed pages that were technically comprehensive but used outdated terminology. The target page used "AI search" exclusively, missing the dominant category term "GEO" used by all four competitors. AI models trained on current content are sensitive to this vocabulary mismatch.

  • 05

    A single well-structured prompt replaces hours of manual audit work

    The benchmark confirms that one standardised prompt reliably surfaces gaps that would take a human analyst several hours to compile manually. This makes the CCI module a high-leverage addition to AI Spider's existing deterministic audit capabilities.

6. Next Steps
  • 6.1 Module build - AI Spider CCI tab: Implementation as a standalone tab within AI Spider. Independent from the core crawl. Accepts target URL plus up to 4 competitor URLs. Outputs all six analytical dimensions in a structured results dashboard.
  • 6.2 Multi-vertical prompt testing: Current benchmark used a single vertical. Additional testing planned across law, healthcare, insurance, and construction verticals to validate prompt robustness across different content types.
  • 6.3 Longitudinal citation tracking: Following CCI-informed content updates, AI citation rates will be tracked across ChatGPT, Claude, Gemini, and Perplexity using RankScan to measure whether closing identified gaps correlates with measurable citation improvement.
  • 6.4 7B+ local model re-evaluation: Once Llama 3.1 8B or Qwen2.5 7B are tested on the same prompt, a minimum viable local model recommendation will be published as an addendum.

Note on Sources

All five URLs used in the benchmark test were publicly accessible pages fetched in May 2025. Content was extracted and included verbatim in the analysis prompt. No model-external knowledge was solicited or used in scoring. Ground truth was compiled manually before running any model tests and was not modified after viewing outputs. Models tested: Claude Sonnet 4.6 (Anthropic), ChatGPT o3 (OpenAI), Gemini 3.5 Flash (Google), Qwen2.5-3B-Instruct (Alibaba, via LM Studio v0.3). All tests conducted May-June 2025.
