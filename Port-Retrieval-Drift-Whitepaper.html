Retrieval Drift Analysis for AI Retrievability_

A two-vertical, three-model benchmark validating entity classification and drift scoring as signals for measuring topical focus and intent alignment. Conducted as pre-build validation for a planned AI Spider module.

Abstract

This paper documents pre-build validation research for a Retrieval Drift Analysis module planned as a future feature addition to AI Spider. It is the third paper in a series validating the planned content intelligence layer of AI Spider alongside the Competitive Content Intelligence module (WP001) and the Coverage Score and Entity Expansion module (WP002).

Where WP001 measured what competitors have that a target page lacks, and WP002 measured whether a page covers what a complete answer requires, this module addresses a third and distinct question: does the page stay focused on answering the user query, or does it drift into topics that dilute its retrieval relevance? A page can be comprehensive and still score poorly if a significant proportion of its entity footprint belongs to unrelated domains.

Research Conclusion

Retrieval drift scoring is a valid and discriminating signal for AI retrievability. All three frontier models produced coherent entity classifications and plausible drift scores. The key finding is a meaningful divergence in how models draw the Aligned/Supporting/Drift boundary: Claude produces the most conservative classifications, Gemini the most aggressive, ChatGPT falls between. This divergence is correctable with calibration. The module will use Claude as the recommended default.

1. Background and Research Motivation

WP001 and WP002 established that content gap analysis and coverage scoring are valid signals for AI retrievability improvement. Both modules address completeness. The Retrieval Drift module addresses a complementary but different problem. Completeness asks: is everything that should be here, here? Drift asks: is everything that is here, supposed to be here?

"A page that discusses backlink analysis, domain authority, and SERP features in the context of an AI visibility query is not incomplete - it is mis-focused. Its entity footprint signals to retrieval systems that the page is about general SEO, diluting relevance for users specifically evaluating AI monitoring tools."

This pattern appeared directly in the WP002 benchmark - the Semrush AI Visibility Toolkit page carried the entity footprint of Semrush's broader SEO platform. That entity bleed could not be measured or scored in WP002's framework. The Retrieval Drift module was designed specifically to surface and quantify it.

Three research questions needed answering before building:

  • Q1 - Is the Aligned/Supporting/Drift classification reliable? Do frontier models apply it consistently and in alignment with manually derived ground truth?
  • Q2 - How much do models disagree on the classification boundary? Does disagreement at the Supporting/Drift boundary produce materially different drift scores?
  • Q3 - Can models reliably estimate competitor drift scores? The competitor comparison feature requires models to estimate drift scores from provided content - is this estimation plausible?

2. Research Methodology

2.1 The Aligned / Supporting / Drift Classification System

Every significant entity and topic on a target page is classified into one of three categories, each with a distinct relationship to the query intent.

Aligned

Directly addresses the query intent. AI models retrieving pages for this query would expect these entities. Their presence strengthens citation likelihood.

e.g. Strategic Advisory, Red Team, Maturity Assessment, Penetration Testing

Supporting

Related to the domain but not central to this specific query. Acceptable but should not dominate the page's entity profile.

e.g. Forrester Wave recognition, SOC integration, Pulse Services

Drift

Moves away from the query intent. Dilutes retrieval relevance. Not wrong for the domain - wrong for this specific query.

e.g. Scattered Spider (adversary), Falcon platform brand, Backlink analysis

Figure 1. The three-tier entity classification system. Retrieval Drift Score = Drift entities / all page entities (lower is better).

2.2 The Four-Stage Prompt

The module uses a four-stage prompt - one more stage than WP002. Stage 2 (competitor validation) is the key structural addition: it anchors Stage 3 classification in what the competitive set actually discusses, preventing models from classifying entities against their own priors.

STAGE 01

Intent extraction

From the query alone, define core intent entities and topics a page must address.

STAGE 02

Competitor validation

Extract common entities from competitors. Becomes the Competitor Entity Universe anchoring Stage 3.

STAGE 03

Entity classification

Classify every significant entity on the target page as Aligned, Supporting, or Drift.

STAGE 04

Drift scoring

Calculate 3 scores, estimate competitor drift, generate prioritised recommendations.

Figure 2. The four-stage reasoning framework.

The full prompt template used across all three models is reproduced below with page content omitted.

// SYSTEM ROLE

4. Key Findings

F1

Retrieval drift scoring is a valid signal

All three models correctly identified primary drift entities in both verticals. The methodology discriminates meaningfully between focused and unfocused pages.

F2

Core drift consensus - boundary disagreement

All three models agreed completely on clearly Drift entities. All disagreement was at the Supporting/Drift boundary. The most actionable output - the core drift entity list - is reliable regardless of model.

F3

Gemini over-classifies Drift consistently

Gemini classified Supporting entities as Drift in both verticals, producing above-range scores. Consistent, predictable pattern correctable with a known calibration offset.

F4

Relative ranking more reliable than absolute score

All three models ranked competitors in the same order despite different absolute scores. For competitor comparison, relative ranking is the operationally useful output.

F5 - New finding unique to this module

The drift cause description is the highest-value output - not the score

Claude's V2 drift cause: "The drift on Semrush's page originates from legacy SEO tooling entities - backlink analysis, keyword research, domain authority, SERP features, and on-page optimisation - that belong to Semrush's broader platform but are irrelevant to an AI visibility query. These entities signal to retrieval systems that this page is about general SEO, diluting its relevance." This paragraph tells the user exactly what to change and why. The score tells them nothing actionable. The module UI will foreground the drift cause description, not the score.

Series finding - across WP001, WP002, WP003

"Across three consecutive benchmarks covering three different analytical tasks, Claude Sonnet 4.6 has been the most calibrated and recommendation-specific model in every test. Gemini 3.5 Flash has shown task-specific patterns: over-inflating coverage scores in WP002, over-classifying entities as Drift in WP003. These are predictable behaviours accommodatable with calibration. The AI Spider module suite will use Claude as the recommended default across all three modules."

5. Implications for AI Spider

  • 01

    Drift cause description is the primary UI element

    Finding F5 establishes that the plain-language explanation of what causes drift is more actionable than the numeric score. The module UI will foreground the drift cause paragraph, with the score displayed as a secondary metric.

  • 02

    Entity classification chips displayed per entity

    The Aligned/Supporting/Drift classification will be surfaced at entity level in the UI - every significant entity on the page labelled with its classification, making it transparent, auditable, and actionable.

  • 03

    Relative ranking alongside absolute scores

    Competitor comparison panel displays both estimated drift score and explicit ranking so users understand comparative position clearly even if absolute scores differ by model.

  • 04

    Gemini calibration offset documented

    If a user selects Gemini, the module displays: "Drift scores from Gemini tend to run 5-15 percentage points higher than Claude due to more aggressive Supporting/Drift boundary classification." Transparent, not hidden.

  • 05

    Drift analysis integrates with CCI and Coverage Score

    An entity identified as Drift that is also absent from the competitor set (via CCI) will be flagged as a double negative - both diluting focus and missing from the competitive entity universe - becoming the highest-priority recommendation across all three modules.

6. Next Steps

  • 6.1 Module build - AI Spider Retrieval Drift tab: Standalone tab with entity classification panel (Aligned/Supporting/Drift chips per entity), drift cause description, three scores, competitor comparison ranking, and prioritised recommendations. Claude Sonnet 4.6 as default model.
  • 6.2 Cross-module entity sharing: Shared entity store across CCI, Coverage Score, and Retrieval Drift tabs enabling cross-module signals - entities that are both Drift and missing from competitor set flagged as highest-priority recommendations.
  • 6.3 RankScan correlation study: Following drift-informed content updates, measure whether citation rate improves via RankScan over 90 days. Results form Working Paper No. 004.
  • 6.4 Gemini calibration study: Systematic testing across 10 additional verticals to establish a reliable calibration offset for automatic application when user selects Gemini.
