Sitemaps: What They Are

What XML and HTML sitemaps are, how they help search engines discover and prioritize your pages, and the best practices for keeping them clean.

A sitemap is a file that lists the pages of a website, helping search engines discover and understand its content more efficiently. While a well-structured site with strong internal linking should theoretically be fully discoverable through crawling alone, sitemaps act as a direct, reliable signal that supplements natural discovery, particularly important for large sites, new sites with few external links, or sites with pages that are difficult to reach through normal navigation. A large-scale study covering more than five billion URLs found that 78% of them were first seen by a search engine through the sitemap rather than through organic link discovery, which underscores how much of the modern web relies on sitemaps as the primary discovery path.

Types of Sitemaps

XML Sitemaps

The XML sitemap is the primary format used for SEO purposes. It's a machine-readable file, typically located at a URL like /sitemap.xml, that lists a site's indexable URLs along with optional metadata such as the last modification date, change frequency, and relative priority. Search engines use XML sitemaps as a hint, not a guarantee, about which pages exist and should be considered for crawling and indexing.

A basic XML sitemap entry looks like this:

<url>
            <loc>https://example.com/page</loc>
            <lastmod>2026-06-15</lastmod>
            </url>

HTML Sitemaps

An HTML sitemap is a page on the website itself, designed for human visitors, that lists and links to the site's main pages in an organized way. While less critical for SEO than they once were, HTML sitemaps can still help users navigate large sites and provide an additional set of internal links that reinforce site structure.

Sitemap Index Files

For large sites with more URLs than a single sitemap file can efficiently handle, typically limited to 50,000 URLs or 50MB uncompressed per file, a sitemap index file is used to reference multiple individual sitemap files, for example separate sitemaps for products, blog posts, and category pages. One technical SEO practitioner found that reducing the per-file limit from 50,000 to 30,000 URLs, which grew a single index from roughly 80 XML files to about 130, actually sped up processing, with Google covering three to four million pages within a couple of days rather than leaving files unprocessed for weeks as before.

Specialized Sitemaps

Some content types have their own sitemap formats or extensions, including image sitemaps, video sitemaps, and news sitemaps, which include additional metadata specific to that content type, such as video duration or publication date for news content, to help search engines index that content more accurately. For news sitemaps specifically, best practice is to include only articles published within the last 48 hours and remove older URLs once they're no longer current.

What Should Be in Your Sitemap

A sitemap should include only the canonical, indexable URLs you actually want search engines to crawl and rank. This means:

  • Only include pages that return a 200 status code, not redirects, 404s, or error pages
  • Only include canonical versions of pages, never duplicate or parameterized URL variants
  • Exclude pages blocked by robots.txt or marked noindex, since including them creates conflicting signals
  • Exclude low-value pages like internal search results, admin pages, or thin filtered and faceted URLs that shouldn't be indexed

A healthy sitemap-to-index ratio is generally considered to be above 80%, meaning at least eight out of every 10 submitted URLs should actually get indexed. Including non-canonical, blocked, or low-quality URLs in a sitemap doesn't just fail to help; it can waste crawl budget and create confusing signals about which pages actually matter.

How Sitemaps Help Crawling and Indexing

Sitemaps are especially valuable in specific scenarios: large websites where the sheer number of pages makes it inefficient for search engines to discover everything through link-following alone; new websites that don't yet have enough external links pointing into them to be crawled and discovered organically at speed; sites with pages that have few internal links pointing to them; and sites with frequently updated content, where the lastmod field helps search engines prioritize recrawling pages that have actually changed.

It's important to understand that submitting a sitemap does not guarantee indexing. Search engines still evaluate each page's quality, uniqueness, and value before deciding to index it. A sitemap tells search engines a page exists and where to find it; it doesn't override quality-based indexing decisions.

Creating and Maintaining a Sitemap

Most modern content management systems generate and update XML sitemaps automatically through built-in features or SEO plugins. For custom-built sites, sitemaps can be generated programmatically, ideally as part of the build or deployment process so they stay in sync with the live site automatically rather than requiring manual updates.

Key best practices for sitemap maintenance include keeping the sitemap dynamically updated so it reflects the current state of the site, using accurate lastmod timestamps only when content has genuinely changed, splitting large sitemaps by content type to make monitoring and troubleshooting easier, and compressing large sitemaps to stay within file size limits and reduce load. Google's Gary Illyes has said that decreasing crawling without sacrificing crawl quality would benefit everyone, a comment that reflects the search engine's own push toward crawling less overall but more efficiently, which makes clean, well-segmented sitemaps more valuable, not less.

Submitting Your Sitemap

Once created, a sitemap should be referenced in the robots.txt file with a line pointing search engines to its location, so any crawler checking robots.txt can find it automatically, and submitted directly through the relevant search engine's webmaster tools, which also provides reporting on how many submitted URLs were successfully indexed versus excluded, and why.

Monitoring this indexing report regularly is one of the most useful diagnostic tools available. A large gap between submitted and indexed URLs often points to underlying content quality, duplication, or technical crawling issues that need investigation.

Common Sitemap Mistakes

Common mistakes include including redirected or broken URLs, which waste crawl budget and create noise in indexing reports; listing non-canonical duplicate URLs, which conflicts with canonical tag signals elsewhere on the site; forgetting to update the sitemap after a redesign or migration; exceeding size limits without splitting into an index file; and blocking sitemap-listed pages in robots.txt, a direct contradiction that confuses crawlers about whether a page should be crawled.

Sitemaps and Crawl Budget

For very large sites, sitemaps play a role in crawl budget efficiency by helping search engines focus crawling resources on the URLs that matter most rather than spending that budget discovering pages through exhaustive link-following. As one technical guide put it, a well-structured sitemap acts as a highly efficient internal linking mechanism, ensuring the most important content receives immediate attention. This becomes increasingly important as site size grows into the tens or hundreds of thousands of pages.

Sitemaps for Multilingual and Multi-Regional Sites

Sites that serve multiple languages or regions face an added layer of complexity: search engines need to understand not just that a page exists, but which language or region it's intended for, and how it relates to equivalent pages in other languages. This is typically handled through hreflang annotations, which can be included either directly in page <head> tags or, more efficiently for large multilingual sites, within the XML sitemap itself. Including hreflang data in the sitemap avoids bloating every individual page's HTML with alternate-language references and centralizes the management of these relationships in one place.

Sitemaps and Fresh Content Discovery

For sites that publish new content frequently, such as news outlets, active blogs, and e-commerce sites launching new products regularly, a well-maintained sitemap plays an outsized role in speeding up discovery of that new content. Some publishers maintain a dedicated, smaller "recent content" sitemap alongside their full sitemap specifically to draw crawler attention to the newest additions without waiting for a full site recrawl cycle.

Sitemaps Are a Support Tool, Not a Substitute

It's worth emphasizing that a sitemap supplements good site structure and internal linking; it doesn't replace them. A site with poor internal linking but a comprehensive sitemap will still struggle with authority distribution and user navigation, even if every page gets crawled. The sitemap ensures discoverability; structure and content quality determine whether those discovered pages actually get indexed and rank well.

Do I need a sitemap if my website is small?
Small sites with strong internal linking and a handful of pages are often fully crawlable without a sitemap, but including one is still considered best practice since it's low effort, and studies show sitemaps are the first discovery path for the large majority of URLs on the web.
How many URLs can a single XML sitemap contain?
A single sitemap file is generally limited to 50,000 URLs and 50MB uncompressed. Sites exceeding this need to split their URLs across multiple sitemap files referenced by a sitemap index file, and some large-site practitioners have found that using a smaller per-file limit actually speeds up processing.
Does submitting a sitemap guarantee my pages will be indexed?
No. A sitemap only tells search engines that a page exists and provides its location; it doesn't guarantee crawling or indexing. Search engines still evaluate content quality, uniqueness, and relevance before deciding whether to index a page. A healthy sitemap typically sees above 80% of submitted URLs actually indexed.
Should I include noindex pages in my sitemap?
No. Pages marked noindex should be excluded from the sitemap, since including them sends a contradictory signal. The sitemap says "please index this" while the noindex tag says the opposite.
What's the difference between an XML sitemap and an HTML sitemap?
An XML sitemap is a machine-readable file intended for search engine crawlers. An HTML sitemap is a page built for human visitors that lists and links to key site pages, primarily aiding navigation and providing supplementary internal links.
How often should my sitemap update?
Ideally, your sitemap updates automatically and immediately whenever pages are added, removed, or significantly changed. Most content management systems and site generators handle this dynamically; manually maintained sitemaps should be reviewed and refreshed regularly to avoid drift from the live site.
